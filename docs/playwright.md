# Автоматичні перевірки і Playwright E2E

## Запуск

З кореня checkout на Linux/Fedora або GitHub Actions з Docker Compose,
Bash і flock:

```sh
bash scripts/test-e2e.sh
```

Альтернатива за наявності npm — `npm run test:e2e`. Node і Chromium
для тестів встановлені всередині runner-образу; локальні Node/браузер
не обов'язкові. Скрипт використовує лише фіксований ізольований проєкт
bordergroup-e2e-42 і --env-file /dev/null, без публікації API/БД назовні.
Наприкінці видаляє тільки контейнери й volumes цього тестового проєкту.

## Що покрито

1. Видима відмова при неправильному паролі.
2. Кабінет ADMIN: користувачі та підрозділи без зайвого redirect.
3. MAIN_KOORD: власна програма й запланований захід.
4. KOORD: направлений workflow свого підрозділу.
5. VYK→KOORD→VYK: подання зафіксованого наказу, відмова виконавцю в
   погодженні й аналізі, авторизоване завантаження PDF, погодження та reload.
6. Активний аналіз і результат не губляться при 45-секундному polling.
7. Помилка моделі залишається видимою (очікуваний 502 перевіряється явно).
8. Вихідний ліміт моделі показує попередження про можливу неповноту.
9. Збережений аналіз відновлюється після reload без нової генерації;
   повторний звичайний POST теж використовує кеш; сторонньому KOORD — 403.

Запити застосунку не мокаються. Зовнішню Ollama замінює окремий model-stub;
лічильник викликів дозволяє перевірити відсутність повторної генерації.
Якість справжнього Qwen цими сценаріями не вимірюється.

## Міграції, ролі та межі покриття

API тестового стенда запускає кореневу історію Alembic. Репетиція включає
синтетичне подання й legacy-висновок: після upgrade перевіряється незмінність
попередніх бізнес-таблиць, alembic check і перенесення висновку в файл.
Вона не замінює резервну копію production.

E2E seed сам готує програму, направлення, призначення й документ, а для
репетиції старої схеми також потрібні ролі. Тому його успіх **не доводить**
повноту початкових ролей на чистому встановленні. Це окремо перевіряють
`tests/test_initial_roles_postgres.py`: upgrade без E2E-фікстури,
повторне заповнення без перезапису назв та створення користувачів через API.
Також вручну відтворено локальний README на порожній БД.

На коді 9e2187c: **109 Python-тестів і 9 Chromium-сценаріїв пройшли**.
Це датований результат релізу, а не гарантія будь-якого нового checkout.
Створення повної програми через усі форми, весь набір правил RF і всі
комбінації підрозділів браузерний набір не покриває.

## Артефакти

`e2e-artifacts/playwright-report/index.html` — звіт;
`test-results` — trace та screenshot за помилки; `compose.log` — логи
за невдачі. Вони і залежності не комітяться. У CI артефакти зберігаються
7 днів; токени в trace належать тільки синтетичним користувачам.
Скриншот docs/images/dashboard.png зроблено на синтетичному стенді.

```sh
python3 -m http.server 9323 --bind 127.0.0.1 --directory e2e-artifacts/playwright-report
```

Після запуску відкрийте http://127.0.0.1:9323.
Джерела: [Playwright CI](https://playwright.dev/docs/ci-intro),
[Docker](https://playwright.dev/docs/docker).
