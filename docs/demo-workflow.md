# Демонстрація повного сценарію

Запуск на порожній локальній БД — за [README](../README.md).
Міграції створюють активні ролі; bootstrap створює тільки demo_admin.
Програми, довідники й накази самі не з'являються. Для демонстрації
використовуйте вигадані назви та документи, не службову інформацію.

## Підготовка адміністратора

Створіть тестовий підрозділ, а в ньому користувачів MAIN_KOORD, KOORD,
VYK і KER з окремими логінами. ADMIN керує довідниками й реєстром,
а не створює програму за координатора. Реєстр наказів можна наповнити
через /docs: авторизуватись як ADMIN, створити запис у /api/orders/,
потім завантажити PDF або DOCX через /api/orders/{id}/versions.
Одного номера без завантаженого файла недостатньо для подання виконання.

## Сценарій у кабінетах

1. **MAIN_KOORD:** створити синтетичну програму з датами, щонайменше
   одним заходом, показником і вимогою підтвердження; направити підрозділу.
   Альтернатива — валідований JSON через /api/program-import/ від MAIN_KOORD.
   Для звіту потрібні розділи №1, №2 і №3 у довіднику: імпорт підтримує
   їх створення; на чистій БД перевірте їх наявність перед генерацією.
2. **KOORD:** відкрити направлену програму та призначити захід VYK.
   Доступ до програми не дорівнює персональному призначенню виконавцю.
3. **VYK:** обрати звітне півріччя, відкрити власний захід, внести
   фактичний результат/дату й номер існуючого наказу, подати виконання.
4. **KOORD:** у тому самому періоді відкрити подання, завантажити
   зафіксований документ. За наявності локальної Ollama запустити
   допоміжний аналіз, перевірити висновок і його відновлення після reload.
   Погодити або відхилити з причиною; без ШІ документ перевіряється вручну.
5. **KER / координатор:** показати прогрес підрозділу, доступні сигнали
   й пояснювані рекомендації; сформувати та експортувати піврічний звіт.
   Для незавершеного півріччя це попередній звіт. Немає автоматичного
   надсилання до НАЗК, а відсутні пояснення чи непогоджені дані потребують дій.

Всі ролі порівнюють один і той самий період. Нуль сигналів не обов'язково
є помилкою: частина RF застосовується після завершення півріччя.
Для зрозумілої демонстрації прострочення використовуйте синтетичний строк
у минулому, а не змінюйте дату сервера. Вже погоджений результат не
переписуйте для покращення статистики.

## Приклади і межі

[Скриншот кабінету](images/dashboard.png) та [фактичні JSON/CSV](examples/README.md)
одержані на окремих синтетичних станах; вони не представляють виробничі
дані. E2E перевіряє підготовлений workflow, але не всі наведені форми.
Створення користувачів після чистих міграцій окремо перевірено через API.

Відео до 3 хвилин записує команда й додає посилання в README. Потрібно
показати продукт і дії людини, а не тільки схему чи слайди. Нотатки
обговорень і первинні матеріали команди можна додати поряд із ai.md;
синтетичні приклади не замінюють доказу обговорення продуктових рішень.
