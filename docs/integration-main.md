# Інтеграція фінального backend у main

Підготовлено від `main` 14589da та фінального `backend` ccb94e4.
Інтегровано Playwright із PR #44; наші CD workflow, SSH-обробник і
скрипт розгортання збережено. Основну гілку агент не зливає.

## Схема БД

Канонічна історія для сервера — коренева `alembic/`.
Додано без зміни SQL міграцію `a20b6e9f1042`, яку вже застосовано
на сервері. На БД із цією ревізією повторне `upgrade head` не
виконує перехід повторно. Не запускати незалежну історію
`backend/alembic/` поверх цієї БД і не змінювати її ревізію через stamp.
Для старої e360c96d9546 міграція відмовляє при непорожніх orders,
evidences або executions — потрібен окремо узгоджений backfill.

## Зберігання файлів

Compose використовує `bordergroup_order_documents` і
`bordergroup_report_exports` у `/app/storage/orders` та
`/app/storage/reports`; UID 10001 має право запису. Це ті самі
назви volumes й шляхи, що використовуються підготовленим серверним релізом.
Файли з backend/var/order_documents та backend/generated_reports виключено
зі складу гілки; оригінали залишаються в backend та локальному checkout.
До серверного розгортання перевірити mount поточного контейнера через
docker inspect і створити резервні копії БД та обох файлових volumes.
Сам deploy.sh зберігає дамп БД, але не архівує файлові volumes.

## Погоджені зміни

- ANAL прибрано з UI, авторизації та нових призначень. Історичні рядки
  користувачів і ролі в БД не видаляються автоматично.
- ШІ аналізує тільки зафіксовану версію наказу конкретного execution,
  після перевірки доступу та SHA-256. Не змінює погодження автоматично.
- Старі Python-тести адаптовано до власності MAIN_KOORD та незалежного
  реєстру наказів; перевірки доступу й відмов збережено.

## Перед розгортанням

Потрібні рев'ю іншого учасника, успішні CI та Playwright для коміту main
після злиття. Лише після цього запускається Manual deployment із повним
SHA цього коміту. До злиття сервер залишається на проміжному релізі.
Після розгортання перевірити health/db, вхід ролей, перегляд старого
наказу та справжню відповідь Ollama на синтетичному документі.
E2E не викликає справжню модель: її якість перевіряється окремо.
