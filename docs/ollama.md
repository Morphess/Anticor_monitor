# Локальний аналіз наказів: Qwen 2.5 3B через Ollama

У стандартній конфігурації працює локальна модель `qwen2.5:3b` у контейнері
Ollama. API викликає `http://ollama:11434/api/chat` у мережі Compose.
У контейнері задано `OLLAMA_NO_CLOUD=1`, порт не публікується на хості.
Текст не передається до Qwen Chat або хмарного API. Для першого скачування
ваг потрібен інтернет; це не хмарний аналіз документа. Заміна
`OLLAMA_BASE_URL` адміністратором змінює цю межу довіри.

## Що аналізується

Координатор відкриває подання й натискає «Проаналізувати наказ».
`POST /api/executions/{id}/analyze` перевіряє роль і доступ, читає
зафіксовану версію наказу, перевіряє розмір та SHA-256. Клієнт не
передає довільний файл чи інший номер наказу. Старого маршруту
`/api/orders/{id}/analyze` немає.

PDF із текстовим шаром і DOCX підтримуються витягувачем. Він також
підтримує TXT, але реєстрове сховище наразі приймає PDF, DOCX та ODT:
дозволені для завантаження формати не тотожні форматам аналізу.
ODT аналізатор не підтримує, OCR для сканованого PDF не реалізовано.
Обмеження: 15 МіБ, 200 сторінок PDF, 40 000 символів витягнутого тексту.
Про обрізання вхідного тексту й вихідного висновку UI повідомляє окремо.

## Збереження та рішення

Готовий текст зберігається у приватному файловому сховищі, у БД —
метадані, ключ і контрольна сума. `GET /api/executions/{id}/analysis`
повертає актуальний висновок або 204, без виклику моделі. Звичайний POST
повторно використовує готовий результат; «Повторити аналіз» передає
`force=true` і створює новий запис. Зміна документа, змісту заходу,
правил чи параметрів моделі вимагає нового аналізу. Ваги, замінені
під тим самим тегом, автоматично не визначаються — потрібен явний повтор.

ШІ порівнює зміст і показує прогалини; погоджує людина. Генерація
залишається довгим HTTP-запитом, не фоновою чергою: активний запит
не переживає перезапуск API. Завершений результат можна отримати пізніше.

## Налаштування і запуск локального demo

З кореня вже підготовленого проєкту за [README](../README.md):

```sh
docker compose -p bordergroup-demo --env-file .env.demo --profile ai up -d ollama
docker compose -p bordergroup-demo --env-file .env.demo exec ollama ollama pull qwen2.5:3b
docker compose -p bordergroup-demo --env-file .env.demo exec ollama ollama list
```

Основні змінні: `OLLAMA_BASE_URL`, `OLLAMA_MODEL`,
`OLLAMA_TIMEOUT_SECONDS` (600, діапазон 30–3600),
`OLLAMA_NUM_PREDICT` (768, діапазон 1–4096). Контекст запиту — 8192.
Це ліміти, не гарантія часу або повноти довгого документа. На CPU
аналіз може тривати кілька хвилин; RAM залежить від моделі й контексту.
Орієнтир для demo — близько 4 ГБ вільної RAM додатково, не універсальна вимога.

Модель утримується в пам'яті ще 5 хвилин після запиту (`keep_alive=5m`).
Це не обов'язково витік. Якщо запитів немає, її можна вивантажити:

```sh
docker compose -p bordergroup-demo --env-file .env.demo exec ollama ollama stop qwen2.5:3b
```

Для production використовуйте поточну конфігурацію сервера й [CD](release.md),
а не другий Compose-проєкт або довільний checkout. Зміна env потребує
перестворення API, а не тільки restart.

## Перевірка

Автотести перевіряють доступ, версію, цілісність, timeout, файлове
збереження та показ висновку з підміною моделі. На сервері команда
отримувала реальний висновок Qwen на синтетичному документі; системної
оцінки точності, середньої затримки чи частоти помилок не проводили.
Якість слід оцінити на наборі відповідних, частково відповідних і
невідповідних документів. [Правила й межі ШІ](ai.md).
