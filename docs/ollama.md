# Аналіз документів через Ollama

Координатор вибирає файл біля наказу та запускає аналіз.
API перевіряє доступ до заходу, витягує текст і передає його Ollama.
Звіт повертається на сторінку; у БД він наразі не зберігається.

## Документи

- PDF із текстовим шаром, DOCX і TXT.
- Максимальний розмір файлу — 15 МБ.
- PDF — до 200 сторінок.
- Витягнутий текст обмежується 40 000 символами.
- Скановані PDF без текстового шару не підтримуються.
- Контекст моделі також обмежений; повноту аналізу довгих документів
  потрібно перевіряти окремо.

## Конфігурація

API використовує:

- OLLAMA_BASE_URL=http://ollama:11434
- OLLAMA_MODEL=qwen2.5:3b

Ollama працює у профілі Compose `ai`, без опублікованого порту.
Моделі зберігаються в іменованому volume `ollama_data`.

## Запуск на сервері

Команди виконуються з каталогу розгорнутого проєкту.
Серверний .env залишається поза Git.

```bash
docker compose --env-file "$HOME/Antikor_monitor/Anticor_monitor/.env" \
  --profile ai up -d ollama

docker compose --env-file "$HOME/Antikor_monitor/Anticor_monitor/.env" \
  exec ollama ollama pull qwen2.5:3b
```

Після готовності Ollama потрібно зібрати й оновити API,
щоб він отримав новий код і змінні середовища.

## Перевірка

Автоматичні тести перевіряють витягування тексту, формування запиту,
тайм-аут, HTTP-доступ та фільтрацію наказів на PostgreSQL.

Локальний сценарій перевірено для головного координатора та
координатора підрозділу з підміною відповіді моделі.
Форму завантаження і показ тестового звіту перевірено в браузері.

Перевірка справжньої моделі на сервері виконується після розгортання,
на синтетичних документах. Її якість і швидкість ще не оцінено.
