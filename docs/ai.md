# Використання ШІ

ChatGPT використовували для обговорення архітектури проєкту,
підготовки правил роботи з AI-агентами та планування налаштування GitHub.

Цей файл доповнюємо під час розробки. Для кожного нового випадку
зазначаємо інструмент, задачу та як команда перевірила результат.

## Фронтенд кабінетів (Claude, Anthropic)

- Задача: шаблони й скрипти кабінетів виконавця, координатора, керівника,
  аналітика та адміністратора під наявний API; заглушки там, де ендпоінтів
  ще немає (роль користувача, реєстр наказів, довідник підрозділів,
  розділи для неадміністраторів, рішення керівника, звіти аналітика).
- Доопрацювання за технічною документацією: перевірка номера наказу
  за реєстром `/api/orders`, додавання наказів координатором, підтвердні
  матеріали й перенесення строків у картці заходу, сигнали Risk Flags
  (вкладка адміністратора, позначки RF у координатора, зведення в
  керівника й аналітика).
- Перевірка: unittest (`tests/test_frontend_pages.py`), ручний прохід
  усіма кабінетами на локальній БД із синтетичними даними; детектор
  на наборі за I півріччя 2026 (зріз 06.07.2026) повертає 29 сигналів.

## Аналіз наказу локальною моделлю Ollama

- Координатор може передати PDF, DOCX або TXT до `POST /api/orders/{id}/analyze`.
  API перевіряє доступ до заходу, витягує текст і надсилає його до Ollama.
- Файл обробляється в пам'яті API й не зберігається. Підтримується до 15 МБ;
  скановані PDF без текстового шару потребують OCR і тут не аналізуються.
- Ollama запускається лише з Compose-профілем `ai`, без опублікованого порту
  на хості. На сервері після оновлення коду запустіть:

  ```sh
  docker compose --profile ai up -d ollama
  docker compose exec ollama ollama pull qwen2.5:3b
  docker compose --profile ai up -d --build api ollama
  ```

- API звертається до `http://ollama:11434` у внутрішній мережі Compose.
  Модель `qwen2.5:3b` завантажується окремо й зберігається у volume `ollama_data`.
  Висновок є допоміжним аналізом: координатор має перевірити його за оригіналом.

## Звітність за вимогами НАЗК (Claude, Anthropic)

- Задача: привести піврічний звіт до структури звіту Порталу доброчесності
  (шапка «Звіт за … півріччя», «Орган», три розділи, групування заходів за
  ризиками, кількість учасників навчань, кольорові стани виконання), брати
  відповідальний підрозділ із призначень виконавців, збирати у виконавця опис
  результату, фактичну дату, стан і значення індикатора; закрити доступ без
  входу до створення/зміни/видалення наказів.
- Перевірка: `tests/test_report_nazk.py`, наскрізний сценарій через API на
  локальній БД із синтетичними даними (звіт JSON/CSV/PDF/друк).
