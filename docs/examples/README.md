# Реальні виходи API на синтетичних даних

Ці файли сформовано 20.11.2026 ізольованим локальним API, а не написано
вручну як очікувані відповіді. Реальна БД сервера й документи користувачів
не використовувались. Версія коду — 9e2187c; базова фікстура — e2e/support/seed.py.

Для прикладу додано порожні розділи №1 і №2 поряд з існуючим №3, окремого
KER у PW-TEAM і встановлено синтетичний строк PW000001 на 01.11.2026,
щоб на зрізі 20.11.2026 продемонструвати прострочення. Подання виконання
для цього заходу не створювали. Це окремий приклад, не той самий стан,
що на скриншоті README або після E2E погодження.

- [report-synthetic.json](report-synthetic.json) — відповідь GET
  /api/reports/{id}/content після POST /api/reports/auto-generate
  для PW-PROGRAM, 2026-H2.
- [report-synthetic.csv](report-synthetic.csv) — фактичний CSV тієї ж
  збереженої версії через /api/reports/{id}/download.csv.
- [recommendations-synthetic.json](recommendations-synthetic.json) —
  фактична відповідь /api/management/recommendations для KER у PW-TEAM.

## Коротка аналітична довідка за цими даними

Один захід не має подання; строк минув на 19 днів. Правило DL_OVERDUE
повернуло критичну операційну рекомендацію перевірити причини затримки
та коригувальні дії. Це не висновок про корупцію чи вину конкретної людини.
Звіт містить 1 невиконаний захід, 0 виконаних і 1 відсутнє пояснення.
Півріччя ще триває, тому звіт попередній; він не є готовим офіційним поданням.

Цей абзац — пояснення фактичного JSON, не додатковий згенерований моделлю
доказ. Для відтворення підготуйте ті самі синтетичні сутності, строки,
роль і зріз через API; не запускайте E2E seed на production.
Числові ID й generated_at залежать від запуску, зміст перевіряйте за
program_id, period, summary та code/object_id рекомендації.
