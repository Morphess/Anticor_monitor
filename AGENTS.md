# Правила роботи агентів над проектом

## Завдання та межі роботи

- Перед змінами прочитай цей файл і призначений GitHub Issue. Звір мету, критерії готовності та файли, яких стосується задача.
- Працюй у межах Issue. Якщо потрібна зміна поза його межами, опиши її в Issue й узгодь із відповідальним розробником.
- Зміни спільних файлів, конфігурації CI, залежностей, схеми БД або контрактів між модулями узгоджуй із командою через Issue.
- Спирайся на затверджені рішення команди. Якщо завдання ще не визначає стек, архітектуру або структуру каталогів, залиш це питання відкритим.

## Git і перевірка змін

- Для кожного Issue використовуй окрему гілку від актуальної `main`. Назва містить номер задачі, наприклад `feat/12-review-queue` або `docs/5-readme`.
- Перед редагуванням перевір поточну гілку та `git status`. Зберігай незакомічені зміни інших учасників.
- Відкривай PR у `main`. У його описі вкажи `Closes #<номер>`, якщо PR повністю закриває Issue.
- Перед злиттям потрібне одне схвалення іншого учасника й успішні перевірки CI, якщо вони налаштовані. Учасник команди виконує `Squash and merge` після рев’ю. Агент не пушить напряму в `main` і не зливає PR самостійно.

## Перед передачею на рев’ю

- Переглянь `git diff`, звір зміни з Issue та запусти доречні перевірки, доступні в репозиторії.
- Тримай поза комітами секрети, локальні `.env`, реальні персональні дані та службові матеріали. Для демо використовуй вигадані дані.
- У підсумку вкажи, що змінив, які перевірки пройшли та що залишилося неперевіреним. Якщо є залежність від іншої задачі, додай посилання на її Issue.
